## 2. 本次已完成的迁移

### 2.1 工程与页面

- 建立 Taro 4.2.1 + React 18.3.1 + TypeScript 5.9.3 + Webpack 5.91.0 独立工程。
- 完成封面、目录、故事、相册、婚礼当天、周边游玩共 6 个页面。
- 封面和目录位于主包；故事、相册、婚礼当天、周边游玩使用 4 个普通分包。
- 保留原 Web 请柬的纸张、红线、章节结构、文案层级与主要交互。
- 使用小程序原生组件和 SCSS 重建，不包含 Next.js、ReactDOM、Tailwind、shadcn/Base UI 或 lucide。

### 2.2 关键行为

- 封面启封使用 `redirectTo`，目录进入章节使用 `navigateTo`。
- 详情页在页面栈存在目录时返回；从外部直接进入详情时回落到目录。
- 导航服务带并发保护，避免快速重复点击造成页面堆栈异常。
- 每页微信好友分享均指向封面，分享内容不依赖发送者的页面状态。
- 相册支持分类、Swiper 滑动、按钮循环翻页、分类切换归零，并防止旧滑动事件覆盖新分类状态。
- 婚礼当天页面包含 4 个日程节点和 3 图自定义弹层，支持循环翻页、圆点、图题和说明。
- 周边游玩保留“一瞥、拾趣、寻味”三个空分组，不虚构地点。
- 地点适配层已实现坐标校验、`openLocation` 和复制地址兜底；生产功能开关保持关闭。

### 2.3 数据与素材

- 公共婚礼数据位于 `src/data`；章节独有数据与素材放在各分包内，避免将全部原图拉入主包。
- 原项目 17 个 SVG 占位图片槽位已作为源素材保存在 `release-assets`，运行素材由脚本转换为优化后的 JPG/PNG。
- 当前运行包共有 20 项本地图片资源。
- 大尺寸头像及设计源文件不进入运行包。
- 所有现有业务数据均为包内静态数据，因此当前版本不需要服务器域名配置。

## 4. 开发、构建与验证

环境要求：Node `>=22.13.0 <25`，npm 10+。本次验证使用 Node 24.14.0。

```sh
npm ci
npm run dev:weapp
```

微信开发者工具应导入项目根目录，编译产物目录已由 `project.config.json` 配置为 `dist/`。

提交候选版本前执行：

```sh
npm run verify
```

`verify` 依次执行 TypeScript 检查、oxlint、测试、素材检查、微信生产构建和包体检查。2026-09-07 的结果如下：

- 运行素材检查：20/20 通过
- Taro 微信生产构建：通过

## 5. 已知风险与技术边界

### 5.1 依赖安全公告

`npm audit --omit=dev` 当前报告 16 项公告：13 moderate、3 critical，主要位于 Taro 4.2.1 依赖链中的 `swiper`、`webpack-dev-server`、`esbuild` 等包。npm 的自动修复建议会将 Taro 降至不兼容的 3.x，因此未运行 `npm audit fix --force`。

当前小程序不渲染外部 HTML、不运行公开开发服务器，也不接收远程业务数据，风险暴露面有限，但发布前仍应检查 Taro 后续稳定版本和安全公告。若升级，所有第一方 `@tarojs/*` 包必须保持同版，并完整重跑自动与真机验证。

### 5.2 尚未完成的真实环境验证

- 当前机器未确认安装微信开发者工具。
- 未使用真实 AppID、开发成员和微信账号验证。
- 未完成 iOS、Android 真机视觉、性能、分享及弱网首次分包加载测试。
- 当前图片仍是占位素材，实际照片可能改变裁切效果和包体。
- 地图功能没有真实地址和 GCJ-02 坐标，保持关闭。

### 5.3 不要擅自改变的边界

- 不要把 AppSecret、上传私钥或其他微信密钥写入源码或提交到 Git。
- 不要猜测婚礼地址、地点坐标、故事日期、平台类目或备案状态。
- 不要为简化配置而引入远程图片、Vercel 外链或 `web-view`；这会增加域名、网络稳定性和合规要求。
- 不要把 `release-assets` 中的大图或设计源文件直接打入运行包。
- 不要使用 `audit fix --force` 接受 Taro 主版本降级。
